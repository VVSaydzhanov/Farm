# Farm — справочник лекарств для приложения «Пилюли»

Здесь два файла, и приложение раз в сутки в фоне проверяет оба:

| Файл | Что в нём | Откуда |
|---|---|---|
| [`catalog/catalog_drugs.csv`](catalog/catalog_drugs.csv) | Подсказки при вводе названия | Составлен вручную |
| [`catalog/gtin.csv`](catalog/gtin.csv) | Код с упаковки → препарат | ЕСКЛП Минздрава + ручные коды |

## Таблица кодов с упаковок

Собирается из выгрузки ЕСКЛП — единого структурированного справочника-каталога
лекарственных препаратов Минздрава. Это единственное место, где связь
«штрихкод — препарат» опубликована открыто: Национальный каталог и API
«Честного знака» доступны только участникам оборота товаров.

**Ограничение, о котором надо помнить:** в ЕСКЛП штрихкод лежит в блоке
предельных отпускных цен, а он заполняется только для ЖНВЛП. Препараты вне
перечня и все БАДы в выгрузку не попадают. Эти пробелы закрываются вручную
через [`source/gtin_manual.tsv`](source/gtin_manual.tsv); то, что не внесено
и туда, остаётся связкой, которую человек заводит сам при сканировании.

Как обновить выгрузку ЕСКЛП:

1. Скачайте с [esklp.egisz.rosminzdrav.ru](https://esklp.egisz.rosminzdrav.ru)
   файл `esklp_ГГГГММДД_active_*.xml` — «Справочник ЕСКЛП в формате XML»,
   полная выгрузка активных записей. Архив около 55 МБ, внутри почти гигабайт.
2. Распакуйте и запустите:
   `python tools/extract_esklp.py путь/к/esklp_..._active_....xml`
3. Проверьте и запушьте — как обычно.

Код в файле приведён к четырнадцати знакам: в ЕСКЛП он записан как EAN-13,
а из кода маркировки приходит GTIN-14 с ведущим нулём.

### Коды, внесённые вручную

`source/gtin_manual.tsv` — БАДы и препараты вне ЖНВЛП. Формат и правила
заполнения описаны в шапке самого файла.

```
# добавили строку в source/gtin_manual.tsv — и:
python tools/extract_esklp.py      # без аргументов: только ручные коды
python tools/validate_catalog.py
```

Без аргументов скрипт не трогает выгрузку ЕСКЛП, а пересобирает каталог
с текущим содержимым ручного файла: добавленные коды появляются, удалённые
исчезают. Чтобы удаление работало, список ручных кодов пишется в шапку
`gtin.csv` строкой `# manual-gtins:` — руками её не трогайте.

Ручная строка перекрывает запись ЕСКЛП с тем же кодом: она выверена
по упаковке в руках.

**Вносить можно только код, считанный с реальной упаковки.** Не по аналогии
с соседней дозировкой, не из интернета без проверки: неверная строка означает,
что приложение подставит человеку чужое лекарство.

## Справочник наименований

**Этот файл собирается скриптом — руками его править не нужно.** Исходники
лежат в `source/`, сборка — `python tools/build_catalog.py`.

Репозиторий **должен быть публичным**: приложение ходит за файлом без авторизации.
Ничего секретного в файле нет — только наименования препаратов, действующие
вещества, формы выпуска и дозировки.

## Адрес, по которому ходит приложение

```
https://raw.githubusercontent.com/VVSaydzhanov/Farm/main/catalog/catalog_drugs.csv
https://raw.githubusercontent.com/VVSaydzhanov/Farm/main/catalog/gtin.csv
```

Они прописаны в приложении в константах `CatalogRepository.CATALOG_URL`
и `CatalogRepository.GTIN_URL`.

`raw.githubusercontent.com` отдаёт заголовок `ETag`, а приложение присылает
`If-None-Match`. Поэтому, если файл не менялся, ответ — 304 без тела:
проверка обновления стоит примерно ничего.

## Формат файла

Обычный текст, разделитель — точка с запятой, кодировка UTF-8, перевод строки LF.

```
# pillbox-catalog version=2026-09-09 count=511
name;inn;form;strength;unit;food
Креон 10000;Панкреатин;CAPSULE;10000;IU;WITH_MEAL
Аспирин Кардио;Ацетилсалициловая кислота;TABLET;100;MG;
Фестал;Панкреатин;;;;WITH_MEAL
```

| Колонка | Обязательна | Что это |
|---|---|---|
| `name` | да | Наименование, как на упаковке |
| `inn` | нет | Действующее вещество (МНН) |
| `form` | нет | Форма выпуска, значение из списка ниже |
| `strength` | нет | Дозировка числом; точка или запятая |
| `unit` | нет | Единица дозировки, значение из списка ниже |
| `food` | нет | Связь приёма с едой, значение из списка ниже |

Правила:

- Строки, начинающиеся с `#`, — комментарии. Версия берётся из первой такой
  строки, из фрагмента `version=…`. **Меняйте версию при каждом обновлении** —
  по ней видно в настройках приложения, какой справочник загружен.
- Строка `name;inn;form;strength;unit` — заголовок столбцов, пропускается.
- Битая строка молча пропускается, а не роняет разбор: одна опечатка не должна
  оставлять человека без подсказок.
- Незнакомое значение `form` или `unit` не ломает запись — просто не заполняется.
- Меньше 20 записей — приложение считает файл испорченным и **не заменяет**
  тот, что уже загружен. Это защита от случайной заливки пустого файла.

### Допустимые значения `form`

`TABLET`, `CAPSULE`, `DROPS`, `SYRUP`, `SUSPENSION`, `INJECTION`, `INHALER`,
`SPRAY`, `OINTMENT`, `SUPPOSITORY`, `PATCH`, `POWDER`, `OTHER`

### Допустимые значения `unit`

`PIECE`, `MG`, `G`, `ML`, `DROP`, `PUFF`, `IU`, `SACHET`, `APPLICATION`, `OTHER`

### Допустимые значения `food`

`EMPTY_STOMACH` — натощак, `BEFORE_MEAL` — до еды, `WITH_MEAL` — во время еды,
`AFTER_MEAL` — после еды. Пустое поле означает, что указания нет.

Значения `ANY` в файле нет намеренно: иначе не отличить «указания нет»
от «указание есть, и оно любое».

## Что лежит в `source/`

| Файл | Что в нём |
|---|---|
| `drugs.tsv` | Торговые наименования: название, вещество, форма, дозировка |
| `drugs_add.tsv` | То же, дополнения. Разделён только для удобства правки |
| `food_by_inn.tsv` | Связь с едой — **по действующему веществу**, с основанием |

Связь с едой задаётся один раз на вещество, а не на каждое наименование.
Иначе неизбежно выйдет, что «Нурофен» помечен «после еды», а «Миг 400»
с тем же ибупрофеном — нет.

### О колонке `food` отдельно

Это **не назначение**. Здесь общее указание из инструкции производителя,
одинаковое для всех препаратов с этим действующим веществом. Врач может
назначить иначе, и его назначение важнее.

Поэтому приложение подставляет значение как подсказку, подписывает
«из инструкции производителя» и позволяет его изменить. И поэтому
`food_by_inn.tsv` заполняется только там, где указание однозначно и не зависит
от показания, дозы и формы выпуска. Во всех сомнительных случаях строки там
нет: пустое поле лучше неверной подсказки.

Сведений о взаимодействиях, показаниях и противопоказаниях здесь нет
и быть не должно — приложение не даёт медицинских советов.

## Как обновить справочник

1. Отредактируйте нужный файл в `source/`.
2. Соберите: `python tools/build_catalog.py`. Версия проставится сегодняшней
   датой автоматически.
3. Проверьте: `python tools/validate_catalog.py`.
4. Закоммитьте **и исходник, и собранный `catalog/catalog_drugs.csv`**, запушьте
   в ветку `main`.
5. Проверка на GitHub прогонит валидатор ещё раз. Если она красная — файл
   битый, **не оставляйте его так**: приложение уже начнёт его качать.

Обновление доезжает до телефонов в течение суток: приложение проверяет файл
не чаще раза в 24 часа.

## Что обязательно сделать до публикации приложения

Текущий список **составлен вручную** по распространённым препаратам и содержит
511 записей, из них у 105 заполнена связь с едой. Возможны неточности
в дозировках и формах выпуска.

Перед публикацией его нужно перегенерировать из открытого
[ГРЛС](https://grls.rosminzdrav.ru/). Брать оттуда только фактические сведения
с упаковки: наименование, действующее вещество, форму, дозировку. Описания,
показания и противопоказания из коммерческих справочников защищены авторским
правом — в этот файл они не попадают и в приложении не показываются.

Приложение не даёт медицинских советов. Справочник существует только затем,
чтобы не набирать «Ацетилсалициловая кислота» руками.
